# 局域网共享程序，各自保存资料

本部署模式仅让同一局域网中的电脑下载同一套枝间程序。导图、历史、附件、PDF、批注和完整备份仍由各自浏览器保存，不进入服务器，不增加共享数据库、账号、遥测或实时协作。现有前端功能、数据库结构和 Windows/安卓运行方式不变。

## 现有用户先看这一条

继续使用原来的 `http://127.0.0.1:4173` 或已安装的枝间 PWA，不必改地址、重装或恢复备份。新的 LAN HTTPS 地址是另外一个来源；即使在同一台电脑中打开，也可能显示空白知识库。这不表示原资料被删除。

不要清除原浏览器配置或站点数据，不要把自己的完整备份分发给其他人。新用户第一次打开 LAN 网页应为空白。

## 自动完成与需要管理员完成的边界

程序已经提供：只读 HTTPS 静态服务、单网卡绑定、允许网段限制、Host 校验、SPA 深层链接、正确的 PDF 工作线程 MIME 和 PWA 缓存、配置检查、证书签名申请及自动测试。

程序不自动执行：安装根证书、修改系统/浏览器信任、开放防火墙、变更网络类别、修改路由器、端口映射、创建开机任务，或进入其他电脑修改设置。没有忽略 TLS 错误或关闭浏览器保护的选项。

若没有现成的受信任 HTTPS 证书，必须先解决证书签发和客户端信任；只有服务代码并不能让浏览器自动信任新的局域网地址。不要用证书警告的“继续访问”替代信任配置。

## 主机配置

要求：主机已有 Node.js 24、项目依赖和生产构建。`vite preview` 仅保留作本机预览；LAN 使用独立的 Node.js HTTPS 静态服务。

机器专用配置放在 `config/lan.local.json`，它被 Git 忽略。参考 `config/lan.example.json`，按真实网络填写：

```json
{
  "listenAddress": "192.168.1.20",
  "port": 8443,
  "publicOrigin": "https://192.168.1.20:8443",
  "allowedClientSubnets": ["192.168.1.0/24"],
  "tls": {
    "certificateFile": "../.lan-private/server-cert.pem",
    "privateKeyFile": "../.lan-private/server-key.pem"
  }
}
```

不要使用 `0.0.0.0`、公网 IP 或不限来源的网段。例子中的 IP 不代表你当前机器的地址。其他电脑必须使用 `publicOrigin` 中的域名/IP 和端口，Host 不匹配会被拒绝。

建议由网络管理员为主机保留固定 DHCP 地址，或使用已配置的固定局域网域名。不要随意改变地址或端口：浏览器按来源保存数据，改地址后不会自动迁移资料。

## 证书准备

### 使用管理员提供的可信证书

1. 如果已有匹配的证书和私钥，将 PEM 文件放入 `.lan-private/`，在配置中填写路径。服务器证书 SAN 必须覆盖 `publicOrigin` 的域名或 IP；证书必须在有效期内，私钥必须匹配。证书文件可包含叶证书及中间证书链。
2. 如果没有私钥及证书，在项目目录运行：

   ```powershell
   npm run lan:cert-request
   ```

   该命令使用已有的 OpenSSL（Windows 可使用 Git 自带版本），生成服务器私钥和 `.lan-private/server-request.csr`，不创建系统信任，不覆盖已有密钥或申请文件。也可通过 `RESEARCHMIND_OPENSSL` 指定管理员批准的 OpenSSL 路径，不需要安装另一份软件。
3. 只把 `.csr` 交给证书管理员签发。**私钥不能发给客户端、上传 GitHub 或放进 dist。**管理员须保留 SAN 和 serverAuth 用途。
4. 将签发的服务器证书保存为配置指定的 `server-cert.pem`，确认证书颁发机构已由管理员合法配置为各客户端信任。

私钥目录应仅部署用户、SYSTEM 和管理员可读。Windows 不完全采用 POSIX 文件权限；若在其他机器上部署，管理员需核对目录 ACL。加密私钥的口令可通过 `RESEARCHMIND_TLS_PASSPHRASE` 提供，不能写入配置或提交仓库。

### 没有现成证书颁发机构

可以选择本项目专用的局域网 CA 文件方案，但必须明确理解：生成 CA 文件不等于安装为系统信任。客户端信任需由你或管理员单独确认，不能由网页静默完成。未配置信任时不得绕过证书警告。

本机在明确授权后已生成文件，均放在受保护且被 Git 忽略的 `.lan-private/` 中：

- `ca-cert.pem`：公开 CA 证书；CA 名称为 `ResearchMind LAN CA 728afe5a`。
- `client-trust/ResearchMind-LAN-CA.cer`：相同 CA 的 DER 格式公开证书，可单独交给需要使用的电脑；该目录还有指纹核对说明。
- `ca-key.pem`：CA 私钥，**绝不能分发**。目录 ACL 仅允许部署用户、SYSTEM 和管理员读取；私钥未使用口令加密，建议将它及 CA 证书保管到受保护的离线位置，服务器运行不需要 CA 私钥。
- `server-cert.pem`：签发后的 HTTPS 服务器证书，匹配当前配置的 IP。继续使用原 `server-key.pem`；没有替换已有密钥或 CSR。

CA 有效至 2031-10-10，服务器证书有效至 2027-10-11（精确时间以证书为准）。CA 不允许签发下级 CA。已验证证书链、服务器用途、IP SAN 和私钥匹配；这不表示 Windows 或任何客户端已经信任该 CA。

客户端只需要公开 `.cer`，**不要复制整个 `.lan-private/` 目录**。核对 CA SHA-256 指纹：

```text
5C:0C:B1:22:39:38:BD:08:6A:64:94:33:06:22:06:CD:89:78:BF:DA:85:33:D5:40:72:96:AE:4F:79:EE:6C:DC
```

管理员批准客户端信任前，应先核对指纹及 CA 来源。导入根证书会赋予该 CA 签发证书的信任，不能把它当作普通程序附件随意安装。本次没有安装任何根证书、改变证书信任或修改防火墙；客户端配置和真实局域网验收仍未完成。

CA 密钥丢失或泄露时，不要静默更换 CA、恢复旧密钥或绕过警告，应联系管理员处理信任撤销及重新签发。证书续期须保持原 HTTPS 来源，提前安排，避免资料空间因改地址而变化。

## 检查和启动

证书就绪后，在项目目录执行：

```powershell
npm run lan:check
npm run lan:serve
```

检查通过后，终端显示 LAN 地址。保持服务运行。默认只监听指定局域网地址的 `8443` 端口；不会占用或改动原来的 `127.0.0.1:4173`。

证书缺失、过期、SAN 不匹配、密钥不匹配、地址被占用或访问被安全保护阻止时停止，处理实际原因后再启动；不要停用保护、换端口规避安全规则或修改浏览器不安全来源白名单。

## 防火墙与网络

在可信的局域网，由管理员核对主机的实际网络类别和防火墙规则。**不要关闭防火墙，也不要无条件开放所有网络、地址或端口。**若需要新增规则，应先批准，并限定：

- TCP 服务端口（例如 `8443`）；
- 主机的指定局域网地址和网卡；
- 需要访问的可信局域网网段；
- 当前批准的网络配置文件及实际运行服务的 Node.exe。

本程序不自动改网络类别或规则；即便程序已监听端口，防火墙、无线客户端隔离或不同 VLAN 仍可能阻止其他电脑连接。检测到拦截后不要绕过，请管理员确认。

## 其他电脑使用

1. 在已信任对应证书的 Chrome/Edge 中，打开主机显示的 HTTPS 地址，例如 `https://192.168.1.20:8443/library`。
2. 首次应看到空白知识库；自行新建导图或导入自己的资料。
3. 验证新建、保存、重开、PDF 导入和阅读；有安装入口时可安装为 PWA。
4. 完成首次程序预缓存后，可继续离线使用已缓存的程序；首次访问和后续程序更新需要主机服务在线。
5. 定期在本机创建完整 `.researchmind` 备份。恢复会替换当前浏览器的数据，不是多人合并。

每台电脑、每个浏览器配置分别保存资料。同一电脑上多人共用同一个浏览器配置，仍会共用该配置的数据；要各自独立，应使用不同浏览器配置或 Windows 账号。本模式不承诺账号级鉴权、同机共享配置隔离、端到端加密或多人实时协作。

## 更新与验证

更新前保留用户备份；运行 `npm run build`，完成审查后重启 LAN 服务。服务启动时只在内存中读取一次编译后的程序文件，不把工程目录作为文件服务器。客户端从原 HTTPS 地址更新缓存；不要变更来源或清理 IndexedDB。

```powershell
npm run test:lan
npm run test:lan:browser
npm run test:public
npm run verify:public
```

Node 测试验证只读接口、网段、Host、路径安全、TLS 主机名/密钥和工作线程。浏览器测试在独立的回环地址、临时浏览器配置中验证两份知识库相互隔离、PDF 保存重开和离线导入；不关闭 HTTPS 校验，不读写用户日常资料。模拟测试不能替代真实第二台电脑、真实证书信任及实际防火墙的验收。

`.lan-private/`、本机配置、证书、CSR 和私钥不得提交 Git 或包含在 Windows 安装包中。
