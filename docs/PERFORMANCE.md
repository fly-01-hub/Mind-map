# 大型导图性能（1.7.9）

当前支持几千个节点，但不保证所有设备、内容和操作始终流畅。未使用思维导图视口虚拟化：全部展开的节点仍占用页面元素。折叠无关分支或用 Ctrl + ] 聚焦当前分支，对大量节点仍有帮助。

## 本次优化

- 常见的叶节点新增/删除、内容修改和单分支折叠通过 Mind Elixir 公开 API 更新，不重建未变主题。引擎本身已完成的编辑或拖动不会被 React 再次重复布局。
- 多分支同时折叠、重排/重新挂接、复杂导入及带关系的结构编辑保留完整刷新。富文本和来源徽标按内容缓存，普通笔记内容更新不改变节点外观时仅更新引擎元数据。
- 不可变树操作复用未变分支，最近 50 次内存撤销记录共享这些分支；引擎和剪贴板等可变对象在边界复制。持久化历史快照仍按原格式保存，数据库和完整备份格式不变。
- 350ms 防抖与串行保存保持不变，只写入自上次成功保存后改变的文档；写入失败不推进成功基线，后续仍会重试。文件夹变动仍立即保存。
- 文档名称变化才刷新链接目标状态；普通编辑不再遍历知识库重复装饰链接。链接装饰键使用版本计数，避免每个节点重复持有完整名称索引。

## 2026-10-14 桌面实测

同一电脑的 Chrome 155，生产构建、Playwright 独立临时配置，十叉合成树，每节点约 200 字符笔记，无图片/PDF。每种情况单次测量，导航打开包含应用初始化；新增测试包括 Tab 插入、输入标题、退出编辑和自动保存。测试只操作合成资料。

| 节点与显示情况 | 优化前打开 | 1.7.9 打开 | 优化前新增并保存 | 1.7.9 新增并保存 |
| --- | ---: | ---: | ---: | ---: |
| 1,000，全展开 | 0.881 秒 | 0.524 秒 | 0.726 秒 | 0.525 秒 |
| 3,000，全展开 | 2.082 秒 | 0.809 秒 | 2.251 秒 | 0.758 秒 |
| 5,000，全展开 | 3.534 秒 | 1.209 秒 | 4.162 秒 | 1.059 秒 |
| 5,000，仅显示根与第一层 | 0.441 秒 | 0.447 秒 | 0.555 秒 | 0.501 秒 |

5,000 全展开的新增到页面完成更新耗时从 4.152 秒降至 0.654 秒；保存延迟包含正常防抖时间。这些是参考测量，不是硬性能门槛或安卓速度承诺。所有测量都完成保存并刷新重开，新增节点仍在。

## 回归与边界

1.7.15 修复连接线在段落、富文本及图片节点重新排版后仍沿用旧尺寸的问题。逐个观察可见节点的边框尺寸，把同一帧的尺寸变化合并为一次连线重绘；平移、缩放以及空闲时不触发额外重绘。新插入的节点也应用相同的段落排版并参与尺寸观察，移除或折叠后释放相应观察器。仅更新渲染，不改写节点内容或数据库。

`e2e/connector-alignment.spec.ts` 在隔离浏览器中建立 1,069 个节点的混合段落／图片导图，把 SVG 端点换算为屏幕坐标后与节点实际边界比较，覆盖打开、改字、折叠／展开、缩放、主题及紧凑布局；另测原生行内编辑、新增段落、媒体延迟变高和空闲不重绘。默认布局的二级以下连线沿节点下方 6 个布局像素的基线延伸，这是引擎原有下划线样式，缩放时同比缩放。

`e2e-public/large-map.spec.ts` 用 5,000 节点验证新增、改字、撤销/重做和刷新持久化，并检查未变主题 DOM 保持连接。`e2e/performance-regression.spec.ts` 覆盖嵌套分支批量折叠/展开。单元检查验证 50 条历史记录共享未变分支、可正确撤销/重做，以及增量保存的并发和失败重试。

已有浏览器回归覆盖富文本、文档链接、选择/光标、拖动、排序、概要/关联线、PDF 节点与连续阅读。安卓只做触屏及桥接模拟、生产资源和 APK 签名/资源比对；没有连接真机验收。

很深的树、成千上万的富文本标题、图片和超大备份仍可能受布局、递归深度、存储空间和设备内存限制。长时间连续操作和后台杀进程也不能由一次桌面测试保证。重要资料定期创建完整备份；不要通过清理浏览器数据或卸载旧版来更新。
